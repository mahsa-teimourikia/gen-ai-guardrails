# Intermediate track

## Track goal

**Design and implement controls.** This track turns the foundational model into provider-neutral engineering practices and scenario-specific implementation plans.

## Who this track is for

This track is for practitioners designing production guardrails, integrating tools or retrieval, and deciding how to handle uncertainty, authorization, and consequential actions.

## What you will be able to do

- Build a risk register and separate policy from implementation.
- Use defense in depth and safe failure behavior at application boundaries.
- Protect untrusted content, tools, data, and the guardrail itself.
- Adapt control patterns to support, extraction, agent, and moderation scenarios.

## Course sequence

| Course | Main question | Core capability |
| --- | --- | --- |
| [01 — Best practices](01-best-practices/README.md) | How should controls be designed? | Apply risk, boundary, failure, evaluation, and operations practices |
| [02 — Scenario cookbook](02-scenario-cookbook/README.md) | How do controls vary by use case? | Compose controls for concrete trust boundaries and consequences |

### 01 — Best practices

**Key concepts:** risk registers, policy boundaries, defense in depth, untrusted content, tool controls, minimization, safe failure, versioning, budgets, evaluation, humans, and incident playbooks.

**Exit criterion:** produce a production-oriented checklist that makes ownership, failure behavior, and evidence explicit.

### 02 — Scenario cookbook

**Key concepts:** tenant-aware support, typed extraction, external writes, content moderation, approval, citations, redaction, escalation, and release checks.

**Exit criterion:** adapt a scenario recipe into a policy, control sequence, and testable release plan.
